# SimplePlane Desktop 0.3.1

修复 TUN 模式与桌面路由列表脱节，以及网络切换期间的启动失败。

## 功能与修复

- TUN 与桌面设置使用同一份直连表、代理表、域名 provider 和默认路由策略。国内网站及其图片、视频域名不再因为只读取旧 TUN 规则而误走代理。
- TUN 支持保存路由后的热更新；新连接使用新规则，已有连接保留原路径。无效配置保留最后一份有效规则。
- 内置域名表在启动阶段编译为哈希集合，避免每条连接扫描大规模域名列表。
- Windows 网络切换时，TUN 启动会等待 DHCP 默认路由和 DNS 就绪，最长约八秒，并跳过残留的 TUN 地址；失败时返回明确诊断。
- 修正桌面界面的静态版本显示，与 Tauri 和 Cargo 版本统一为 0.3.1。

## 验证

- Windows TUN：65 项单元测试、2 项可运行集成测试通过；4 项依赖独立网络环境的测试跳过。
- 已完成本机真实 TUN 启动与共享规则加载验证：百度、B 站及图片资源、淘宝、京东、QQ 走直连，Google 走代理；七个 TLS/HTTP 探测均成功。
- WLAN 地址变化后重启 TUN，百度、B 站和 Google 再次访问成功。

GitHub Actions 从本次提交重新构建 Windows x64 和 macOS ARM64 安装包及 updater 签名，最终构建结果以对应运行记录为准。上传更新服务时使用同平台安装包及其配对的 `.sig` 文件。

## 范围

本版未增加通用 UDP 转发或 IPv6 直连。运行中物理网络改变后仍需重连 TUN；启动阶段等待 DHCP 不等于自动迁移已有连接。HTTP/3 链路的偶发超时和大文件完整性问题仍需继续排查，本版不宣称已经解决。
