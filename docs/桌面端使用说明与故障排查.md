# SimplePlane 桌面端使用说明与故障排查

这份说明面向第一次使用代理软件的人。先按“5 分钟开始使用”操作；遇到问题时，直接到后面的“故障排查”按现象查找。本文依据仓库中当前桌面端界面和实现编写，适用于 Windows x64 与 macOS Apple Silicon 安装包。Linux、Windows ARM 和 Intel Mac 不在当前发布流程的构建范围内。

## 先弄清楚：它能做什么

SimplePlane 桌面端是一个连接到远程服务器的客户端。电脑上安装客户端，并不等于已经有可用的代理线路。你还需要一组**与服务端一致**的节点信息：服务器地址、端口、传输协议、加密方式和密钥。请向节点提供者索取；如果你自己部署服务端，请使用部署时的实际配置。不要把软件首次显示的示例地址和 `your-cipher-key` 当成可用账号。

软件提供两种连接方式：

| 方式 | 适合谁 | 会影响哪些程序 | 额外条件 |
| --- | --- | --- | --- |
| 一键代理（系统代理） | 初次使用，建议先选它 | 遵循操作系统代理设置的浏览器和应用 | 一般无需 TUN 驱动；macOS 修改系统代理可能受系统权限限制 |
| 一键 TUN | 已经能用系统代理，但有程序不走代理 | 通过虚拟网卡接管更多网络流量 | Windows 需要管理员权限；macOS 当前实现需要为 TUN 程序配置免密 `sudo`；配置错误可能影响网络 |

“系统代理已开启”只说明客户端尝试设置了系统代理，**不等于远程服务器已经连通**。以实际访问结果和“日志”中的错误为准。某些应用会忽略系统代理，此时可使用 TUN，或在该应用自身设置代理。

## 5 分钟开始使用

1. 从项目的正式发布包获取与你电脑匹配的安装文件：Windows x64 选 Windows 安装包，Apple Silicon Mac 选 macOS ARM64 的 `.dmg`。安装包内包含代理程序和 Java 运行时，普通使用不需要自行安装 Java、Node.js 或 Rust。不要下载 Android APK 当桌面安装包。
2. 安装并打开 **SimplePlane**。Windows 使用安装程序完成安装；macOS 打开 `.dmg`，将应用拖到“应用程序”文件夹再启动。若操作系统提示来源未验证，请先确认文件确实来自可信的项目发布渠道，再通过系统提供的“仍要打开”等选项处理；不要为不明来源的安装包关闭系统防护。
3. 点击左侧 **代理配置**，找到 **远端服务器**。将 `Host` 改成节点地址（IP 或域名），将 `Port` 改成节点端口；按照节点提供者的信息选择 `Transport`（HTTP/2 或 HTTP/3 QUIC）、`Cipher`，填写 `Key`。这五项必须与服务端匹配。拿不准时询问节点提供者，不要靠猜。
4. 点击页面右上角 **保存**。看到“配置已保存”后回到 **控制台**。如果之前已经连接，先点 **全部停止**，再重新连接，使新配置生效。
5. 点击 **一键代理**。等待 **Proxy Local** 显示“运行中”、**端口状态**显示“监听中”，再用浏览器打开一个你希望通过代理访问的网站测试。如果网站打不开，请继续看“故障排查”，不要只看按钮的成功提示。
6. 不用时点击 **全部停止**。如果停止后电脑仍无法正常联网，点击 **恢复网络**，再检查系统代理设置。

首次使用先不要改“本地设置”“路由规则”和“TUN 模式配置”。默认本地端口是 `1080`，SOCKS5 与 HTTP 代理共用该端口。控制台中某些尚未刷新或旧版本显示的端口数字，最终以“代理配置”保存值和“端口状态”为准。

### 只有一个 YAML 文件时如何导入

在 **代理配置 → 远端服务器** 点击 **导入 YML**，粘贴内容或选择 `.yml`/`.yaml` 文件，再点击弹窗里的 **导入**。它支持 `remoteServers` 列表、`servers` 列表、单个服务器对象，以及顶层列表。例如：

```yaml
remoteServers:
  - host: example.com
    port: 9090
    transport: http2
    cipher: chacha20
    cipherKey: "请替换成实际密钥"
```

导入后核对卡片里的 `Transport`、`Cipher`、`Key`，然后再点页面右上角 **保存**；“导入成功”本身不等于已经保存或连接。**当前桌面端只把第一张服务器卡片写入运行配置**，所以不要把“导入了 3 个节点”理解成已启用 3 个节点或自动切换。需要换节点时，把要使用的节点放到第一张卡片，再保存、停止、重连。

## 界面各区域怎么用

### 控制台

- **一键代理**：启动本地代理并尝试设置系统代理。新手的首选入口。
- **一键 TUN**：启动本地代理，再尝试启动虚拟网卡。若 TUN 启动失败，程序会尝试退回系统代理模式，界面会显示警告；请核对控制台的“代理模式”和 **TUN Adapter** 状态。
- **全部停止**：断开连接，并尝试停止 TUN、停止本地代理、还原此前的系统代理设置。
- **恢复网络**：网络异常时使用；会尝试停止服务、还原或关闭代理，并检查 DNS。它不是“重新连接”。执行后再检查能否正常访问普通网站。
- **Proxy Local**：电脑本地负责接收代理请求的服务。显示“运行中”和“监听中”只证明本地端口可用，不证明远端节点可用。
- **TUN Adapter**：虚拟网卡服务。使用“一键代理”时保持“已停止”是正常的。
- **系统代理**开关：打开相当于连接系统代理模式，关闭相当于断开连接；它并非只改一个独立开关。

控制台两个服务卡片里的“停止”都会调用整体断开。`Proxy Local` 的“重启”会以**系统代理模式**重新连接，因此使用 TUN 时请用“全部停止”后再点“一键 TUN”。

### 代理配置与路由规则

`Host` 是远程服务器的地址，`Port` 是远端监听端口，不能填本地 `1080`，除非你的远端服务确实监听这个端口。`Transport` 必须与服务端相同：HTTP/3 QUIC 通常走 UDP，HTTP/2 通常走 TCP。`Cipher` 和 `Key` 必须匹配；`none` 只应在你明确知道服务端也使用 `none` 时选择。

**本地监听端口**通常保持 `1080`。若改了端口，需要保存并重连；如果 TUN 配置中的 `[proxy] socks5_addr` 仍指向旧端口，也要同步修改。`HTTP 代理`开关决定系统 HTTP/HTTPS 代理是否启用。集群策略、负载均衡、超时和连接数属于高级设置，没有明确需求先保持原值。

在 **路由规则**中，`proxy` 表示走远端节点，`direct` 表示直接连接。`默认路由`决定没有匹配规则时怎么走；“代理域名”和“直连域名”每行写一条域名，`#` 开头的行会被忽略。修改后到 **代理配置** 页面点击右上角 **保存**，再停止、重连。若某个网站“连接成功但没走代理”，先检查它是否落入“直连域名”或默认直连规则。TUN 页里的 `[routing]` 是另一份配置，不能用这个页面替代。

### 预设、日志与更新

**预设**可保存当前配置，并通过“应用”切换。应用后建议回到“代理配置”核对内容，再停止、重连。预设可能包含密钥，分享预设文件或截图前请遮挡敏感信息。

**日志**可切换查看 `proxy-local` 和 `tun-adapter`。连接失败时，先看最近几行；排查 TUN 时切到 `tun-adapter`。日志页“清空”只清空应用内显示/内存中的日志，不会修复连接。当前界面没有直接提供“运行 TUN 诊断”的按钮，故障排查主要依靠日志和状态。

程序启动后会尝试检查更新。若出现“发现新版本”，可选择“稍后提醒”或“立即更新”；下载或安装失败时，继续使用当前版本，并从可信的项目发布渠道手动下载匹配平台的安装包。

## TUN 模式：系统代理可用后再尝试

TUN 模式会改动网络路由和 DNS。开始前，先确认“一键代理”确实可以访问目标网站，并记录你原本使用的网络/VPN 设置。一次只运行一种模式，切换前先点“全部停止”。

1. 在 **代理配置** 确认远端节点 `Host`、本地监听端口已经保存。
2. 打开 **TUN 模式**，在配置文本中检查 `[bypass]` 下的 `proxy_remote_ips`。如果远端 `Host` 是 IP，这里必须填实际远端 IP，否则 TUN 可能把访问节点本身的流量再次导回虚拟网卡，导致“显示运行中但完全无法上网”。若 `Host` 是域名，也应由节点提供者确认它解析到的 IP，并在这里填写需要绕过的实际 IP。默认文件中的示例 IP不能代替你的节点。
3. 若改过本地端口，检查 `[proxy] socks5_addr` 是否为 `127.0.0.1:你的端口`。不要随意修改虚拟网卡地址、DNS 监听地址、MTU、路由段。
4. 点击 TUN 配置页右上角 **保存**。如果提示 `Invalid TOML`，说明配置语法有误，例如引号或方括号缺失；撤销最近的编辑并重新保存。
5. 回到控制台，点 **一键 TUN**。确认 **TUN Adapter** 显示“运行中”、控制台“代理模式”显示“TUN 模式”，并用浏览器和原先不遵循系统代理的应用分别测试。

Windows 首次启动 TUN 若提示权限不足，关闭客户端后右键 **SimplePlane → 以管理员身份运行**，再重试。macOS 当前桌面实现以非交互 `sudo` 启动 TUN，不能在弹窗里输入密码；若提示免密 `sudo` 未配置，需让熟悉 macOS 管理的人员按日志给出的**实际程序路径**配置权限。此项会授予该 TUN 可执行文件较高权限，务必确认安装包来源和路径。没有这项配置时，继续使用“一键代理”即可。

## 故障排查：按现象找

先做一次通用检查：**全部停止 → 核对节点五项信息 → 保存 → 一键代理 → 查看“端口状态”和日志 → 打开网站测试**。每次修改配置后都重新连接。以下表格按你看到的现象选择：

| 现象或提示 | 常见原因 | 怎么处理 |
| --- | --- | --- |
| 安装后打不开窗口 | 安装包平台不匹配、安装不完整，或系统阻止启动 | 核对 Windows x64/macOS ARM64；重新从可信发布渠道下载安装。Windows 如提示缺少 WebView2，请按系统提示安装运行时后重试。 |
| “JRE not found” / “proxy-local.jar not found” / “tun-adapter not found” | 安装包资源不完整，或被安全软件隔离 | 重新安装完整发布包；查看安全软件隔离记录。不要仅把单个 `.exe` 从安装目录拷到别处运行。 |
| “端口已被占用，复用外部进程” | 其他代理软件或旧进程占用了本地端口 | 先退出其他代理/VPN 软件，再“全部停止”并重连；或在“代理配置”改一个未占用的本地端口并保存、重连。被复用的外部进程未必是 SimplePlane，不能据此判断节点已连接。 |
| Proxy Local 显示“异常”或端口“未监听” | 本地服务未启动，配置无效，或进程退出 | 到“日志”看 `proxy-local` 最近的错误；优先核对本地端口是否被占用、配置能否保存，再重连。 |
| Proxy Local 运行中，但目标网站打不开 | 节点地址/端口/协议/加密/密钥不匹配，服务器离线，或网络阻断 | 与节点提供者逐项核对；尤其确认 HTTP/3 QUIC 的 UDP 端口或 HTTP/2 的 TCP 端口在服务端及防火墙开放。先用一个确定可用的节点测试。 |
| 浏览器能用，某个应用不能用 | 应用忽略系统代理，或自己有代理设置 | 检查该应用自己的代理设置；可填本地 `127.0.0.1:1080`（按应用支持的 HTTP/SOCKS5 类型），或者在满足权限条件后使用 TUN。 |
| 显示“代理已激活”，但系统仍直连 | 系统代理设置未生效，或该网站被路由规则设成直连 | 先看 `proxy-local` 日志中是否有“系统代理设置失败”；检查操作系统代理是否指向 `127.0.0.1` 和当前本地端口，再检查“路由规则”。macOS 上即使系统代理设置失败，连接按钮也可能显示成功。 |
| 一键 TUN 提示“已降级到系统代理模式” | TUN 缺权限、配置错误，或虚拟网卡程序启动失败 | 看 `tun-adapter` 日志中的具体原因；先确认系统代理可用。Windows 可尝试以管理员身份运行；macOS 按上文处理 `sudo` 权限。不要把“降级”当作 TUN 已成功。 |
| TUN 显示运行中，却完全断网 | `[bypass] proxy_remote_ips` 未填真实节点 IP、DNS/路由异常，或 VPN 冲突 | 先点“全部停止”，必要时点“恢复网络”；核对实际节点 IP 和 `socks5_addr`，暂时退出其他 VPN/代理后再试。 |
| 切换节点/规则后仍像旧配置 | 只保存了文件，运行中的代理未重启；或导入了多个节点但使用的是第一张卡片 | 核对第一张节点卡片与保存提示，点“全部停止”再连接。 |
| 关闭软件后仍无法上网 | 系统代理、DNS 或路由未完全恢复 | 重新打开客户端点“恢复网络”；再到系统网络设置检查代理是否仍指向 `127.0.0.1`、DNS 是否仍是 TUN 地址。若原本使用公司 VPN/自定义代理，请恢复原来的设置，而非一律关闭。 |
| 更新失败 | 下载、签名或发布资源异常 | 保留当前版本，稍后再试；需要升级时从可信发布渠道手动获取完整安装包。 |

### 不会用的两个排查指标

- **端口状态“监听中”**：只说明本地服务在等请求。它不能证明远端服务器可达。
- **TUN Adapter“运行中”**：代表启动检查通过；部分平台在规定时间内未确认网卡时也可能先标为运行中。遇到断网，以实际访问结果为准，先停止和恢复网络。

## 数据在哪里，求助时提供什么

桌面端把用户配置放在系统配置目录下的 `SimplePlane` 文件夹：Windows 通常是 `%APPDATA%\SimplePlane`，macOS 通常是 `~/Library/Application Support/SimplePlane`。主要文件有 `proxy.yml`（桌面配置）、`proxy-java.yml`（启动时生成给本地 Java 服务读取）、`tun.toml`（TUN 配置）和 `presets.json`（预设）。这些文件可能包含节点地址和密钥，**不要公开上传原件**。

求助时请提供：操作系统和安装包版本、使用“一键代理”还是“一键 TUN”、控制台两个服务的状态及端口状态、复现步骤、日志里最近的报错。截图或粘贴日志前，遮住密钥、服务器地址以及私人域名。如果 TUN 改坏网络，先执行“全部停止”和“恢复网络”，恢复联网后再整理信息。

> 说明：本文描述的是当前仓库的桌面客户端。项目根目录 README 中的 `start-tun.sh`、`start-tun.ps1` 和 Dashboard 使用流程面向源码运行，普通安装包用户无需执行那些构建命令。
