# 常驻部署验收

本次交付面向运营方长期使用的真实订阅后台。账号和授权使用持久存储，登录走 AuthSystemSimple，管理员以指定 issuer 下的准确 subject 绑定。

| 需求 | 设计和实施 | 可观察的验收结果 |
|---|---|---|
| SUB-01、SUB-03 | 核实运营方指定的身份。订阅服务使用独立数据库与 OIDC 客户端。 | 真实管理员经浏览器回调可以保存授权，普通账号不能访问管理员表单。重启后授权仍存在。 |
| SUB-04、SUB-05 | 只公布已经配置好设备 CA 的受保护节点。 | 用户确认设备后，客户端签名领取实际清单，通过所列地址完成业务往返。 |
| SUB-07、SUB-08 | 凭据在主机受限目录生成或由管理员交互输入。服务设置内存上限和重启策略。 | 服务重启后恢复，管理员可以从受信浏览器再次登录。单独核对公网 QUIC 连通性。 |

既有决定为暂缓申请公网证书。运营方专用受信浏览器可以使用私有 CA。面向普通用户的系统浏览器和发布客户端还需满足其 TLS 信任要求。

### 首次核查（2026-11-23）

远端 212.64.14.155 的既有 SSO 容器处于 exited，配置的 issuer 为回环 HTTP 地址。其配置指向的 MySQL 库为 `sso_authsystem_v2`。按登录名和 subject 查找 `zhh` 均无匹配，同机也未发现其他含 `sso_user` 表的库。部署材料可以先校验和就位，授予管理权限需要已确认的真实账号。

### 常驻实例验收（2026-11-23）

| 项目 | 结果 |
|---|---|
| 身份与后台 | 使用 AuthSystemSimple 官方管理工具初始化正式管理员。订阅后台按其 OIDC subject 授权，在专用 Firefox 完成 TLS 验证、OIDC 登录和回调。 |
| 保存与持久化 | 在后台为一次性验证账号保存立即到期、设备名额为 0 的授权，独立查询 MySQL 验证其内容。重启订阅后台后记录仍然存在，管理员可以再次登录。验证记录已清理。保存提示仅在提交成功后的页面出现。 |
| 运行与证书 | 常驻目录为 `/opt/simpleplane-subscriptions`。身份服务、订阅后台、会话存储和节点容器均配置重启策略及内存上限。私有 CA 签发的 IP 证书已载入本机专用 Firefox，远端每日续期检查计时器已启用。 |
| 节点 | `cn-01` 已启动，主机 UDP 443 返回 QUIC v1 版本协商，连接 ID 匹配。节点就绪后，从运营方 Windows 再发 4 次 TCP 和 4 次 UDP 到公网 443，远端网卡收到 4 次 TCP SYN 和 0 个 UDP 包。当前 `standard` 清单为空。 |

### 运营入口

在部署用的 Windows 账户下，双击桌面上的「SimplePlane 管理后台」，即可通过专用 Firefox 打开 [运营后台](https://212.64.14.155/admin/grants)。其他设备需要信任站点证书。新版界面见[运营后台验收](operations-console.md)。

1. 管理员在「用户管理」里新增账号，或按登录名搜索已有账号。
2. 管理员在用户详情选择节点组、有效天数和设备名额，点击「保存授权」。单击「停止订阅」可停止续签。
3. 当该组有已发布节点时，用户在支持订阅的客户端选择「登录并同步节点」，在浏览器登录确认设备或扫码确认。客户端领取该设备的节点配置和短期证书。用户可在「我的设备」解除绑定。

在远端运行 `cd /opt/simpleplane-subscriptions && docker compose ps` 查看四项服务，运行 `systemctl list-timers simpleplane-subscription-renew.timer` 查看下一次私有证书检查。节点对公网发布前，需核对云安全组及上游入口的 UDP 443 放行情况，完成外部客户端 QUIC 握手和实际转发验证。普通用户还需有可验证的 HTTPS 信任链。

### 正式线路更正（2026-11-24）

上面的 UDP 443 探测结果仅对应控制面主机上的验证节点。正式线路来自 `ops/subscriptions/standard-nodes.json`。两个公网入口均由 nginx 监听 UDP 9090，转发到本机 19090。保留原有 chacha20 手动配置，按设备证书为订阅流量选择独立 AES 密钥。

管理主机在 `pki/issuers` 保管每个节点独立的设备 CA，订阅后台仅挂载签发所需的材料。发布命令为 `python3 manage.py publish zhh-1` 和 `python3 manage.py publish zhh-2`，分别将已验收的节点加入 `standard` 并重载订阅后台。加载或健康检查失败时恢复之前的清单。该命令不会把控制面验证节点加入正式组。

两项发布均于 2026-11-24 完成。分别从公网使用原有手动客户端配置和有效的设备订阅凭据，通过每个节点的 9090 端口完成实际 TCP 与 UDP 回显；未提供设备证书时，仅使用订阅 AES 密钥转发失败。共享监听器另行通过了外部 CA 和过期证书拒绝、活动连接在设备证书到期时关闭的回归测试。

使用正式账号 `zhh` 在浏览器确认一台临时设备后，由该设备签名请求线上清单。实际返回上述两个名称、地址和 9090 端口，两个短期证书的公钥均匹配该设备提出的 TLS 公钥。验收完毕只解绑本次临时设备，再次请求清单返回 HTTP 403。

`zhh-1` 原先固定信任的自签证书已于 2026-10-10 过期。现网保留原信任公钥，另行签发有效的 CA 证书和独立的 IP SAN 服务端叶证书，分别使用旧客户端信任配置与新清单 CA 完成公网验证。该主机的 `zhh1-tls-renew.timer` 已启用，每天检查叶证书。手机完成过设备授权后，在订阅页面点击「同步节点」即可读取已发布的两条线路。
