# 订阅运营后台

## 需求与验收

| 编号 | 运营任务 | 验收条件 |
|---|---|---|
| OPS-01 | 查找和新增用户 | 管理员可按登录名、显示名或账号 ID 查找 AuthSystemSimple 用户；创建真实本地账号并可同时开通订阅。重复登录名不覆盖原账号。 |
| OPS-02 | 管理授权和设备 | 选择用户与已有节点组，设置有效期和设备数，查看授权、停止续签、解绑单台设备。原账号和设备继续可用。 |
| OPS-03 | 管理分组 | 创建、改名、分配或移除节点，同一节点可进入多个组。组内节点和授权人数可查；仍在使用的组禁止删除。 |
| OPS-04 | 管理节点 | 查看、添加、编辑、上线、下线和删除停用的节点。新节点生成独立设备 CA 和订阅密钥，管理员可下载节点端接入材料。已部署的两条线路自动纳入 standard。 |
| OPS-05 | 确认变更 | 查看操作记录，清单下一次同步反映生效的分组和上线状态；解绑后不能续签。普通账号不能操作后台。 |

## 设计和实施顺序

1. MySQL 保存组、节点元数据、关联和审计。首次导入既有部署节点与授权组；重启保留管理员调整。
2. 设备签名、五分钟凭证、OIDC 管理员白名单与 CSRF 沿用原实现。清单按数据库中的有效关联签发。新节点的设备签发私钥和订阅密钥加密落库；节点侧只领取转发所需的密钥和公开设备 CA。
3. 以数据库最小权限视图读取身份；受限开通接口使用 AuthSystemSimple 同款 Argon2 参数及身份审计格式，不向管理页面提供密码哈希。订阅授权、设备和审计使用同一事务。
4. 管理入口提供概览、用户、分组、节点和操作记录，支持窄屏。保留已有后台书签和用户侧设备页。
5. 执行旧功能回归、权限和清单变更测试；在远端用临时用户、临时分组验证登录与分配，核对 zhh 与两个真实 9090 节点。

## 日常使用

- **给人开通**　在「用户管理 → 新增登录用户」设置登录名和初始密码，选择节点组、有效天数及设备数。对于已有的 AuthSystemSimple 账号，搜索后打开用户详情即可授权。「保存授权」按提交当天重新计算有效期。
- **按人分配不同线路**　在「节点分组」创建分组，勾选线路并保存。然后在用户详情选择该组。每份用户授权对应一个组，同一节点可被多个组使用。
- **接入新机器**　在「节点管理 → 添加节点」保存草稿，下载服务端接入包和节点程序。在新 Linux 主机按包内说明安装，把输出的公开 CA 粘贴回详情，放通所选 UDP 端口，上线后加入目标组。接入包含节点密钥，由节点运维方保管。用户通过客户端登录、确认设备并同步。
- **撤销**　在用户详情停止整份订阅，或只解绑指定设备。已签发的设备证书最多还有五分钟有效期。节点下线影响含该线路的所有组；再次上线会沿用原分组。
- **核对**　在「操作记录」查看操作者、时间和对象。在「运营概览」查看已发布节点、所属组和授权人数。「已上线」表示已允许向该组下发，链路可用性需要实际连接验证。

## 部署与恢复

身份库对订阅数据库账号仅开放目录视图与两个存储过程。首次部署需执行 `python3 manage.py console-identity`。订阅库使用 Flyway V2 保存目录、节点密钥密文和审计，旧目录首次导入后以数据库为准。备份需同时保留订阅数据库及安装配置里的原始 challenge key，以便解密已保存节点的签发材料。节点安装程序由 `node-runtime.jar` 挂载，接入包附有该程序的 SHA-256 校验值。

单机部署沿用 AuthSystemSimple 数据库身份模式。其默认配置在重启时生成临时 OIDC 密钥，即使已经挂载签名库。使用相同版本的 AuthSystemSimple 源码与原始发布包执行 `python ops/subscriptions/build-identity.py <源码目录> <原始包> <输出目录>/identity.jar`。将输出包置于 Compose 文件旁。Compose 显式启用现有 PKCS#12 签名库，沿用 SDK 的签名、受众、有效期和 nonce 验证。升级身份服务时应再次构建适配包。

## 2026-11-24 验收记录

| 范围 | 环境与观测 |
|---|---|
| OPS-01、02 | 正式站点的 Firefox 中，`zhh` 新建临时身份并一并授权。重置密码后，第二个浏览器配置以新密码通过真实 OIDC 登录并批准设备。停订后设备续签返回 HTTP 403，管理员可解绑该设备。 |
| OPS-03、05 | 同一临时设备先领取一条线路。管理员将另一条正式线路分配给临时组，该设备下次签名请求即取得两条。普通账号访问用户管理返回 HTTP 403。正式 `zhh` 的设备清单独立核对为两条 9090 线路，其临时验收设备解绑后续签返回 HTTP 403。 |

| OPS-04、05 | 将测试机输出的公开 CA 保存到详情页，上线并分组后，签名清单增加第三条测试线路。下线后下一次清单恢复为两条，可以删除下线节点。 |
| 兼容性 | Maven 运行 4 项集成测试，含并发名额、重放防护、解绑及动态分组。单独从公网以旧手动配置和设备证书配置连接 `54.172.101.190:9090`，两种配置均完成 TCP 与 UDP 回显。 |
| 界面 | 正式管理员登录后打开概览、用户、组、节点、详情和操作记录。桌面 1440 像素宽和手机 390 像素宽的概览均可浏览。见[正式后台截图](operations-console.png)。 |
