# 远端灰度与退出条件

按 SUB-08 逐级执行。每阶段记录实际环境、构建 SHA-256、断言结果、服务状态和清理，后续阶段不能从前置阶段推断成功。

1. 在管理主机检查可用内存、当前 nginx 和业务容器、磁盘空间、80/443 监听、证书工具和既有 OIDC 部署。测试资源使用唯一的临时目录、专用数据库/用户、Redis 前缀、新设备和签发 CA。未经基线比对不修改既有反代站点。控制服务和额外的测试 JVM 不放在 891 MiB 的正式转发机。
2. 在管理主机先跑真实 Linux QUIC 进程的回环接入专项。限制测试进程组的内存和最长运行时间。合法设备请求得到 200，无证书、其他节点 CA 和过期证书均失败，保持的连接在证书到期时关闭。记录负例前后同一入口的成功正例。
3. 本轮使用灰度 CA 与 IP SAN，在独立浏览器配置中验证信任和精确回调。测试账号与节点组从正常管理入口开通。将公网根信任、证书签发及自动续期保留到正式发布验收。
4. 新 Windows 桌面和 Android 客户端在未连接代理时登录。测试同机浏览器和手机扫描桌面屏幕、拒绝、过期、重复扫码、设备上限和解绑。至少执行一次跨公网真实 TCP 与 UDP 往返，校验回复内容和设备/节点隔离。对已经建立的连接计时验证撤回窗口，同时观察仍获授权设备和原有手工入口。
5. 清理临时监听、进程、测试账号、权益、凭证及挑战文件，保留脱敏结果。复核已有服务状态和重启数。任何一阶段证据不完整时记录具体原因，修复后复验。

复验时先构建管理、转发与本地代理三个 jar。使用 `scripts/prepare-subscription-canary.py setup --key <SSH密钥路径>` 创建测试环境，保留它打印的本机运行目录。此目录包含临时凭据，仅在测试机使用。将目录中的 `root.crt` 导入一次性 Firefox 配置 `firefox`，以匹配的 Playwright 驱动运行 `scripts/test-subscription-browser.py --run <运行目录> --firefox <现有浏览器路径>`。

远端业务测试还需在本次远端运行目录创建 `venv` 并安装 `cryptography` 和 `aioquic==1.3.0`。测试脚本的 `--remote-key <SSH密钥路径> --observe-expiry` 使用隔离网络内的实际客户端与计时探针。`--relay <本地代理jar>` 验证从当前测试机跨公网的实际路径。两种结果分别记录。桌面 UI 复验需向调试包注入本次公开 CA、使用带运行标识的调试凭据命名空间、启动独立的本机 WebView2 调试端口；二维码解码使用 OpenCV。

最后执行 `scripts/prepare-subscription-canary.py cleanup --run <运行目录> --key <SSH密钥路径>` 回收专用数据库、容器与临时文件。桌面 UI 测试还需关闭测试进程并清掉该运行标识的调试配置与系统凭据。
