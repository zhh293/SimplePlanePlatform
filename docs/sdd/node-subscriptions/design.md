# 节点订阅设计

## 浏览器认证和设备绑定

认证和管理页面可共用一个有公网信任证书的 IP 入口。OIDC issuer 固定为部署配置中的 HTTPS URL，回调精确注册。反代分别路由授权服务器和订阅服务的路径。管理服务集成 AuthSystemSimple 的 Spring Boot starter，从安全上下文取得 subject。管理员角色来自管理侧显式授权，不能由注册用户自行编辑。使用 IP SAN 的证书与自动续签，公网 80 上的 ACME HTTP-01 challenge 路径与现有站点共存。[IP 证书说明](https://letsencrypt.org/2026/03/11/shorter-certs-certbot)

扫码是订阅服务的设备绑定事务。OIDC 继续使用 SDK 已支持的授权码与 PKCE，无需改变所有现有 OIDC 客户端。桌面创建密钥和配对请求，服务保存公钥、设备名称、随机公开用户码、独立高熵轮询秘密摘要和五分钟有效期。二维码仅含官方 HTTPS 确认页与公开用户码。确认页通过 SDK 登录、显示设备名、核对短码，使用带 CSRF 的 POST 确认或拒绝。同机系统浏览器打开相同确认页，客户端轮询状态。轮询遵从服务端节流；设备用其私钥签署服务端单次挑战才能领取或续签。请求凭证与公开二维码分离。

## 权益和清单

管理服务持久化账号、节点、授权组、有效期和设备，绑定和名额在同一数据库事务内提交。用户标识为 issuer 与 sub 的组合。节点清单只返回仍有权访问的节点。每个用户和设备的快照包含版本、稳定的节点 ID、地址、端口、传输、公有 CA 和 TLS 名称。客户端先完整校验并暂存信任材料，再原子替换该来源的清单。撤销、到期或账号切换时清理该来源连接和设备会话。

## 转发入口

### 设备 API

设备公钥编码为 Base64 DER SubjectPublicKeyInfo，曲线为 P-256。浏览器设备确认后，客户端通过领取接口提交配对秘密及对单次服务端挑战的 SHA256withECDSA 签名。服务端决定设备 ID、节点组和证书有效期。刷新时验证同一设备公钥。请求中的用户 ID、任意服务器地址、CA 路径或角色不能扩大权益。

设备接口面向原生客户端，浏览器会话对这些接口不授予权限。浏览器确认、设备管理与管理员操作采用 SDK 会话和 CSRF。管理员由固定 issuer 下预配置的 subject 集合限定。设备名只用于显示，公钥指纹与设备 ID 用于校验。证书签发私钥从节点对应的管理端密钥库加载，私钥不随清单分发。

Android Keystore 密钥不可导出，而现有 Netty 与 Rust QUIC 实现分别运行于 JVM 和原生 TLS 库。设备保留长期绑定密钥，每次续签另生成一个本机短期 TLS 密钥。设备用绑定密钥对版本、设备 ID、单次挑战、短期 TLS 公钥的规范 Base64 编码逐行签名，管理服务仅为签名内的公钥签证。修改公钥使签名失效。设备证书与清单公开部分均不能独立建立连接。短期私钥仅交由本机受保护的数据面，最长五分钟。长期绑定密钥无需跨语言导出。

使用独立的 HTTP/3 mTLS 监听地址。每个订阅节点有独立的设备证书签发信任域；管理服务按权益给设备公钥签短期 clientAuth 证书，证书截止时间取授权到期与签发后五分钟的较早值。私钥留在设备。节点配置显式选择订阅模式并提供专用设备 CA，配置不足时拒绝启动。QUIC 复用双向 TLS 持钥证明和服务器身份校验；受保护入口须验证握手、禁用 0-RTT 并关闭已过期连接。已有手工节点按原配置接入。同组其他节点也须有各自的信任域；严禁将同一份共享密钥配置导入与旧节点相通的认证旁路。控制服务中断时现有凭证仅可使用到其截止时间。

## 数据和部署边界

复用两端已经支持的 aes-gcm-v2 业务帧，签发清单包含仅用于该订阅监听的 32 字节帧密钥。独立设备 CA 的 mTLS 校验发生在接收任何业务帧之前。帧密钥与任何旧共享入口的密钥必须独立。

控制服务、SDK 的 Redis 存储和签发材料部署在管理侧。设备私钥通过 Android Keystore 及桌面系统凭据设施使用，日志和导出仅包含公开材料。远端灰度先检查入口、IP 证书及内存预算，然后用独立实例、专用测试 CA、测试节点组和测试账号运行。记录基线 PID、重启数、已有监听、可用内存；若同机预算不足，使用隔离主机，避免重演正式节点 OOM。清理以本次创建的实例和测试数据为边界。

### 当前服务的配置与启动

订阅服务使用独立的 Java 17+ Maven 工程。先从 AuthSystemSimple 构建并安装 `sso-client-spring-boot-starter:0.1.0-SNAPSHOT` 到同一 Maven 仓库，再运行 `mvn -f subscription-server/pom.xml verify`。用 `java -jar subscription-server/target/subscription-server-1.0.0-SNAPSHOT.jar` 启动管理服务。Flyway 在专用 MySQL 库创建订阅表。

部署配置见 `subscription-server/src/main/resources/application.yml`。运营方提供 HTTPS 公网 origin、固定 OIDC issuer、机密客户端凭据及精确的 `/sso/callback`。MySQL、Redis、SDK 查询与加密密钥、订阅挑战 HMAC 密钥均通过部署环境注入。管理员由 `SP_ADMIN_SUBJECTS` 指定。为每个节点配置稳定 ID、组、地址、TLS 名称、公开服务 CA、专用设备签发 PKCS#12 与独立的帧密钥。公开入口反代浏览器与设备 API，限制录入请求速率和大小。

转发进程从 `-Dsimpleplane.deviceCaFile=/path/to/device-ca.crt` 加载本节点设备 CA。灰度桌面编译时可通过 `SP_SUBSCRIPTION_CA_PEM` 加入单次测试 CA；调试配置的信任仅在对应测试包生效。正式浏览器和正式客户端的公网信任按本轮决定延期。

## 两种客户端共用公网 9090

两台正式线路沿用同一公网 UDP 端口和原有服务端证书。兼容监听器请求设备证书。TLS 验签通过且仍在有效期内的连接使用该节点独立的订阅 AES 密钥，到期主动断开。没有提交设备证书的旧客户端沿用原有 chacha20 密钥。两种模式按连接确定，不根据解密是否成功重试另一种密钥。订阅服务只下发订阅密钥。现有强制 mTLS 的监听器继续要求每一条连接都携带设备证书。
