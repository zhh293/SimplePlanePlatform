# 远端 UDP 灰度验收计划

日期：2026-11-21。用户授权在现有远端灰度测试，要求真实案例及全面覆盖。

## 隔离与恢复

优先使用 20.78.53.111 的独立目录、临时 systemd 服务、随机测试密钥及单独端口；记录正式服务 PID、重启计数、jar/config 哈希和 UDP 计数基线。不给正式用户切换节点，不替换正式 jar。临时服务设置资源及存活时间上限，结束后清理本次服务/监听/转发，复查正式服务基线。
若云侧限制新公网 UDP 端口，先验证可达性，再选择可回滚、仅匹配测试来源的入口；不把 SSH TCP 转发结果宣称为公网 QUIC 验证。

## 覆盖矩阵

| 范围 | 验收 |
|---|---|
| 构建身份 | 灰度 jar 来自本轮已验源码，记录 SHA-256；客户端也使用新构建 |
| 承载/加密 | H2/H3 × 现有三套加密，记录实际公网/转发路径 |
| 真实业务 | UDP DNS、STUN Binding、NTP（对照远端直连基线）、有证书验证的真实 HTTP/3 GET；无法访问的目标单列原因 |
| TUN 数据面 | 生产 IP/UDP/FakeIP 处理路径承载真实非 DNS UDP；区分包注入与真实 Wintun |
| 边界/隔离 | 空包、1/1472/1473、连续数据报、并发多控制关联、多目标、错误来源、FRAG/畸形报文 |
| 生命周期 | 建立取消、控制断开、空闲、灰度节点重启后重连，旧数据不复活，FD/关联回收 |
| 网络/压力 | 受控低速/突发及必要的灰度专属故障注入，记录成功率、延迟分位、队列/丢包与资源；不对正式网卡设置全局 netem |
| 回归/清理 | HTTP CONNECT/SOCKS TCP、TLS 网页与已存在正式服务健康；结束后灰度监听消失，正式服务未重启 |

结果只根据实际观测填写；公共服务自身不响应、云防火墙、应用协议不支持与代理缺陷分开归因。功能成功不等同于原生 UDP 时延或生产负载容量保证。
